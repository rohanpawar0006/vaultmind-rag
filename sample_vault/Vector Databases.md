# Vector Databases: Storage & Indexing

Vector databases specialize in storing high-dimensional numerical representations (vectors) generated by [[Embedding Models]] and executing Approximate Nearest Neighbor (ANN) search at scale.

## Popular Options

- **ChromaDB**: An open-source, lightweight, embedded vector store designed for fast prototyping and local persistence. Chroma runs in-process with Python, requiring zero external server infrastructure. It supports DuckDB/SQLite persistence and uses HNSW (Hierarchical Navigable Small World) graphs for fast similarity lookups.
- **Qdrant**: Written in Rust, offering payload-based filtering, gRPC interfaces, and distributed clustering.
- **Milvus / Pinecone**: Cloud-native, distributed vector databases designed for billion-scale vector workloads.

## Distance Metrics

1. **Cosine Distance**: Measures the angle between two vectors ($1 - \cos(\theta)$), invariant to vector magnitude. Best for normalized text embeddings.
2. **Euclidean Distance (L2)**: Measures straight-line distance in Euclidean space. Sensitive to document length if vectors are unnormalized.
3. **Dot Product (Inner Product)**: Rapid computation, equivalent to cosine similarity when embeddings have unit length ($L_2 = 1$).

For VaultMind-RAG, **ChromaDB** is selected because it runs locally without credentials, guarantees offline execution, and embeds cleanly inside Streamlit applications.
